# Several languages — native Next.js i18n

No i18n library. Next's own pattern: a `[lang]` segment, a proxy for detection, JSON dictionaries. Before implementing, read the i18n guide in the project's bundled Next docs (`node_modules/next/dist/docs/`) — this Next renamed middleware to `proxy.ts` and details may differ from training data. The bundled guide is the how; this file is the agency's choices.

## Sub-interview

One at a time, with real URL examples — that's how a non-technical user sees the choice:

1. **Which languages?**
2. **Which is the main one?**
3. **Main language in the URL?** Show both: `yoursite.com/es/about` + `yoursite.com/en/about` vs `yoursite.com/about` (main) + `yoursite.com/en/about`. Recommend the main one unprefixed — shorter URLs for most visitors.

## Agency choices

- Locale config in `lib/i18n.ts`: `locales`, `defaultLocale`, `Locale` type — the single source every other piece imports.
- Routes move under `app/[lang]/`, and `app/[lang]/layout.tsx` replaces the root layout — `<html>`/`<body>` move into it, typed `LayoutProps<'/[lang]'>`; it takes the param, sets `lang` on `<html>`, and `generateStaticParams` covers all locales.
- Dictionaries: `dictionaries/<locale>.json`, read server-side by a `getDictionary` with per-locale dynamic imports — a locale's words never ship in another locale's bundle.
- `proxy.ts` detects (cookie, then Accept-Language) and routes:
  - prefix-always → redirect unprefixed paths to the detected locale.
  - main-unprefixed → rewrite unprefixed paths to `/<defaultLocale>` internally, and redirect explicit `/<defaultLocale>/…` URLs to the unprefixed form — one canonical URL per page.
  - The matcher excludes `api`, `_next/static`, `_next/image`, `favicon.ico`, `sitemap.xml`, `robots.txt` (per the bundled proxy docs) — otherwise the favicon and sitemap get locale-rewritten and 404.
- SEO on every page: `alternates.languages` (hreflang incl. `x-default`) via metadata; the sitemap lists each locale with its alternates. With main-unprefixed, every URL emitted for the default locale — hreflang, canonical, sitemap — is the unprefixed form: the prefixed one redirects, and redirecting hreflang targets get dropped by crawlers.
- The starter's own texts (header, footer, home) move into the dictionaries — the project starts fully translated, not half.

Verify: every language reachable at its URL; no page serves both a prefixed and an unprefixed main-language URL; `lang` correct per locale; hreflang present; `pnpm build` passes.
